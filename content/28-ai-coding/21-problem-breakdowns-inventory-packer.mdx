Тебе дан список предметов, у каждого есть вес и размер. Склад выдаёт корзины (bins) с двумя лимитами: по весу и по размеру. Нужно распределить каждый предмет по корзинам так, чтобы ни одна корзина не превысила ни один из лимитов. Результат — map из названия предмета в id корзины, в которой он лежит. Цель — минимизировать количество корзин.

![Иллюстрация](/content/aicoding--problem-breakdowns--inventory-packer/2ae025b991.svg)

Три предмета, упакованные в две корзины. В bin 0 лежат Monitor (8kg, 6size) и Keyboard (2kg, 3size), они заполняют лимит по весу, а в bin 1 лежит Mouse (1kg, 1size), потому что из-за лимита по весу в bin 0 для неё не осталось места

У правил есть несколько ограничений, которые стоит разобрать. Предметы нельзя делить между корзинами, а оба лимита действуют одновременно, поэтому корзина с Monitor и Keyboard из примера выше заполнена по весу, хотя по размеру в ней ещё осталась небольшая щель для Mouse. Склад даёт тебе один метод, который возвращает уже открытые корзины в порядке создания, и другой, который открывает новую корзину и возвращает её id.

Это классическая задача bin packing. Найти абсолютный минимум корзин — NP-hard, то есть неизвестен полиномиальный алгоритм, который всегда находит оптимум. Зато можно выбрать быструю эвристику, то есть стратегию, которая обычно даёт почти оптимальный ответ, хотя и отказывается от гарантии оптимума, и получить близкое к оптимальному количество корзин на тех входах, которые нас интересуют.

###### Паттерн: Greedy & Bin Packing

First-Fit и First-Fit Decreasing — классические жадные эвристики для bin packing. Ты кладёшь каждый предмет в первую подходящую корзину и никогда не возвращаешься назад, жертвуя идеальным ответом ради быстрого и близкого к нему.

## Решение 1, First-Fit

Самая простая рабочая эвристика — First-Fit. Для каждого предмета, в порядке поступления, ты проходишь по уже существующим корзинам и кладёшь предмет в первую, где ещё хватает места. Если не подошла ни одна, открываешь новую корзину для этого предмета и переходишь к следующему.

Это чисто [жадный](https://www.hellointerview.com/learn/code/greedy/overview) алгоритм. Никакого ранжирования, оценок или заглядывания вперёд. Побеждает первое допустимое размещение, а новая корзина открывается, только когда ни в одной из существующих нет места.

![Иллюстрация](/content/aicoding--problem-breakdowns--inventory-packer/121e9df31c.svg)

First-Fit раскладывает шесть предметов по четырём корзинам

На диаграмме показан пример с шестью предметами (w3, s4), (w5, s4), (w4, s4), (w6, s4), (w3, s6), (w5, s6), упакованными в порядке входа. Первые четыре предмета имеют размер 4. First-Fit объединяет их в пары так, что оба лимита соблюдаются. Bin 0 принимает (w3, s4) и (w5, s4): суммарный вес 8 и размер 8. Bin 1 принимает (w4, s4) и (w6, s4): вес 10 и размер 8. Следующему предмету (w3, s6) нужно ещё 6 единиц размера, но в bin 0 и bin 1 уже лежит размер 8, поэтому 8 + 6 = 14 превышает лимит по размеру, равный 10. Он открывает bin 2. Последний предмет (w5, s6) упирается в ту же стену в bin 0 и bin 1, а также в bin 2, потому что 6 + 6 = 12 всё ещё больше лимита по размеру. Он открывает bin 3. В итоге шесть предметов занимают четыре корзины.

First-Fit

```
def pack(self, items: List[Item]) -> Dict[str, int]:
    assignment: Dict[str, int] = {}
    for item in items:
        placed = False
        for b in self.warehouse.get_bins():
            if b.can_fit(item):
                b.add_item(item)
                assignment[item.name] = b.bin_id
                placed = True
                break
        if not placed:
            new_bin = self.warehouse.create_bin()
            new_bin.add_item(item)
            assignment[item.name] = new_bin.bin_id
    return assignment
```

В коде стоит отследить несколько деталей. Проверка на помещаемость учитывает оба лимита сразу. Метод сравнивает вес кандидата с оставшимся весом корзины, а размер — с оставшимся размером, и для размещения должны пройти оба сравнения. Если любой из лимитов оказывается ограничивающим, предмет отклоняется, и цикл переходит к следующей корзине. Когда предмет куда-то попал, `break` останавливает обход; без него цикл продолжил бы проверять последующие корзины, хотя предмет уже размещён, и, в зависимости от того, как записывается назначение, ты можешь записать id более поздней корзины вместо той, в которую предмет реально попал. Ветка «открыть новую корзину» — то место, где кандидаты чаще всего пропускают шаг. Склад выдаёт свежую пустую корзину и её id, но сам предмет туда не кладёт. Ты должен сам добавить предмет в новую корзину, а затем записать назначение на id этой корзины. Забыть любое из двух — частая ошибка, и тесты её ловят.

### Сложность

Пусть n — количество предметов, а b — количество уже открытых корзин. Каждый предмет запускает не больше одного прохода по существующим корзинам, который стоит O(b) (то есть объём работы растёт линейно с b: на каждый предмет приходится один проход по текущему списку корзин), плюс возможный вызов открытия новой корзины в конце. Размещение всех n предметов обходится в O(n · b).

В худшем случае каждый предмет открывает собственную корзину, тогда b = n, и общая стоимость равна O(n²). На практике корзины заполняются, b остаётся небольшим по сравнению с n, и цикл близок к линейному. В любом случае время работы приемлемо. Эта задача проверяет не скорость.

### Где ломается

First-Fit без проблем проходит базовый тест и тест с четырьмя одинаковыми предметами. Сбой проявляется на тесте с большим каталогом, который прогоняет тридцать предметов через склад с лимитами (вес 15, размер 10). Каталог составлен враждебно. Первые пятнадцать предметов имеют размер 4, а последние пятнадцать — размер 6.

First-Fit сначала видит предметы размера 4. Два предмета размера 4 дают в сумме размер 8, это помещается. Три предмета размера 4 дают размер 12, это не помещается. Поэтому First-Fit заполняет первые семь корзин парами предметов размера 4, каждая заканчивается на размере 8 и с запасом укладывается в лимит по весу. В bin 7 оказываются последний предмет размера 4 и первый предмет размера 6 (размер 4 + 6 = 10, ровно на лимите).

Теперь приходят оставшиеся четырнадцать предметов размера 6. В каждой существующей корзине с парой размера 4 уже лежит размер 8, а 8 + 6 = 14 превышает лимит по размеру. Ни одна из них не может принять предмет размера 6. Каждый предмет размера 6 открывает собственную свежую корзину и лежит там в одиночестве. Итоговое количество — 22 корзины при бюджете в 18.

Код корректен, лимиты соблюдены. Просто он рано зафиксировал кучу «почти полных» корзин, в которые потом никто не помещается.

## Решение 2: First-Fit Decreasing

Сначала отсортируй предметы. First-Fit попал в беду потому, что заполнил bin до size 8 мелкими предметами раньше, чем появились крупные. Если бы крупные пришли первыми, они открывали бы bin на size 6, а мелкие потом встали бы в оставшиеся 4 единицы каждого bin. Предметы те же, лимит bin тот же, но результат полностью другой, потому что изменился порядок.

У такого порядка есть название. First-Fit Decreasing (FFD) сортирует предметы по «габариту» в порядке убывания и затем запускает точно такой же цикл First-Fit. Эвристика для «габарита» — weight + size. Одного size на этом конкретном наборе данных тоже хватило бы, потому что именно size заканчивается первым, но сумма обеих величин делает ключ разумным и тогда, когда ограничивающим фактором становится weight. Представь каталог гантелей, где каждый предмет — (w8, s1), а лимит — (w10, s20). Ключ только по size посчитает все предметы равными и оставит порядок на усмотрение порядка поступления, а weight + size по-прежнему поставит более тяжёлые гантели впереди лёгких и даст тяжёлым предметам первый шанс на пустые bin. Ни один ключ не универсально оптимален, и если нужно что-то более принципиальное, можно нормализовать каждую ось по её лимиту (поделить weight на лимит по weight, а size на лимит по size, чтобы обе величины попали в [0, 1], и сложить их), но weight + size — простой вариант, который разумно ведёт себя на каталогах, где может ограничивать любая ось (ограничивающий фактор — та ось, у которой ёмкость заканчивается первой).

![Иллюстрация](/content/aicoding--problem-breakdowns--inventory-packer/4de01f7da0.svg)

First-Fit Decreasing раскладывает те же шесть предметов по трём bin

На диаграмме те же шесть предметов, что и раньше, отсортированные по weight + size по убыванию, так что последовательность такая: (w5, s6)=11, (w6, s4)=10, (w3, s6)=9, (w5, s4)=9, (w4, s4)=8 и (w3, s4)=7. Обрати внимание, что (w3, s6) и (w5, s4) равны по ключу и дают 9. Какой из них окажется первым, зависит от того, что стабильная сортировка в Python сохраняет исходный порядок ввода среди равных элементов, и в других языках стабильность сортировки работает так же. Запуск First-Fit на этом порядке даёт три bin вместо четырёх. В bin 0 попадают (w5, s6) и (w6, s4), он заполняется до weight 11 и size 10. В bin 1 попадают (w3, s6) и (w5, s4), он заполняется до size 10. В bin 2 попадают два самых мелких предмета. В каждом bin лежит пара, потому что крупные предметы открывали bin на size 6, а мелкие их дозаполняли.

First-Fit Decreasing

```
def pack(self, items: List[Item]) -> Dict[str, int]:
    sorted_items = sorted(items, key=lambda i: i.weight + i.size, reverse=True)
    assignment: Dict[str, int] = {}
    for item in sorted_items:
        placed = False
        for b in self.warehouse.get_bins():
            if b.can_fit(item):
                b.add_item(item)
                assignment[item.name] = b.bin_id
                placed = True
                break
        if not placed:
            new_bin = self.warehouse.create_bin()
            new_bin.add_item(item)
            assignment[item.name] = new_bin.bin_id
    return assignment
```

В этой версии стоит разобрать несколько деталей. Код копирует items перед сортировкой, а не сортирует на месте, потому что этот список передал нам вызывающий код, и он ждёт, что список останется нетронутым. Мутация была бы побочным эффектом, которого тесты не ожидают. Весь механизм после сортировки — это тот же код First-Fit из предыдущего решения. Изменился только порядок, в котором приходят предметы, и именно это одно изменение сокращает число bin с 22 до 15. Сам ключ сортировки, weight + size, — простой вариант, который справляется с каталогами, где может ограничивать любая ось. Среди других разумных ключей — max(weight, size) или взвешенные комбинации, учитывающие соотношение лимитов, но weight + size — самое короткое, что можно написать, не игнорируя при этом целую ось.

### Почему по убыванию, а не по возрастанию

Сортировка по возрастанию на самом деле ухудшила бы результат, потому что «сначала мелкие» — это примерно то, как уже выглядел несортированный каталог. Мелкие предметы объединяются в пары, заполняют bin до size 8 и не оставляют места для крупных, которые приходят позже. Порядок по убыванию переворачивает проблему: крупные предметы открывают bin, а мелкие заполняют оставшиеся промежутки.

Крупные предметы разместить сложнее, потому что им нужны почти пустые bin, а мелкие могут проскользнуть почти в любой промежуток, который оставил более крупный предмет. Размещать сложные случаи первыми, пока bin пусты, — стратегия, которая даёт им лучший шанс лечь чисто.

### Сложность

Сортировка занимает O(n log n). Цикл First-Fit — те же O(n · b), что и раньше, где b — число открытых bin. Итого O(n log n + n · b), что в худшем случае сворачивается до O(n²), когда каждый предмет открывает собственный bin и b = n. На практике bin заполняются, b остаётся небольшим, и доминирующим слагаемым становится сортировка. В любом случае это тот же порядок величины, что и у First-Fit, с небольшой аддитивной надбавкой, и сортировка не является дорогой частью решения.

### Почему это проходит

На каталоге из тридцати предметов FFD выдаёт 15 bin, что заметно меньше бюджета в 18 bin. В каждом bin лежит пара предметов, и каждый bin заполнен до size 10 или size 8. Нет наполовину пустых bin, которые ждут предметов, не способных прийти. На каталоге из восьми предметов для базовой упаковки FFD выдаёт 3 bin против 4 у First-Fit. На тесте с четырьмя одинаковыми предметами он использует 2 bin и равен First-Fit, потому что, когда все предметы одинаковы, порядок не даёт преимущества.

FFD не оптимален. Для классической одномерной задачи bin packing существует доказательство, что FFD использует не более (11/9) · OPT + 6/9 bin, где approximation ratio показывает, насколько ответ эвристики близок к доказуемому минимуму. OPT — это и есть минимальное число bin, и эта оценка говорит, что ответ FFD в худшем случае отличается от OPT примерно на 22% плюс небольшая аддитивная константа. Правда, эта оценка предполагает один лимит. В этой задаче два лимита (weight и size), а сортировка идёт по weight + size, так что классическое доказательство напрямую не применимо, и разрыв в принципе может быть больше. Практический вывод в любом случае тот же. FFD доказуемо близок к оптимальному на стандартном bin packing и хорошо ведёт себя на реалистичных каталогах с двумя лимитами, поэтому здесь он выходит на 15, с запасом укладываясь в бюджет 18 bin. Если нужна точная оптимальность, а не гарантия близости к ней, остаются branch-and-bound или integer programming (формулировка упаковки как системы ограничений, которую передают solver), но оба подхода гораздо медленнее и оправданы только на небольших входных данных.

## Бенчмарки

Количество bins на трёх тестовых наборах данных для shipping.

| Набор данных | Товары | Bins у First-Fit | Bins у FFD |
| --- | --- | --- | --- |
| basic catalog | 8 | 4 | 3 |
| four identical (7, 5) | 4 | 2 | 2 |
| adversarial catalog | 30 | 22 | 15 |

First-Fit работает нормально, пока входные данные не упорядочены против тебя. На basic catalog он использует 4 bins, а FFD — 3: выигрыш небольшой, но не драматичный. На фикстуре с четырьмя одинаковыми товарами обе эвристики дают одинаковые 2 bins: когда у всех товаров одинаковый размер, никакой порядок сортировки ничего не меняет.

Разница 22 против 15 на adversarial catalog — это то, ради чего написан тест. Каталог детерминированный и специально составлен так, чтобы эксплуатировать слабое место First-Fit. Всякий раз, когда во входных данных смешаны товары, которые «мешают bins объединяться в пары», и товары, которым «нужны пустые bins», несортированный First-Fit приходит к такой картине.

## Выводы

Если ты застрял на этой задаче, больше всего помогает такой взгляд: каждое решение варьирует что-то своё. First-Fit варьирует только правило размещения и считает порядок входных данных фиксированным. Это работает, пока входные данные не патологические, но ломается, когда реальный поток данных со склада присылает сначала мелкие товары. First-Fit Decreasing оставляет то же правило размещения и вместо этого варьирует порядок входных данных, и именно это единственное изменение снижает количество bins с 22 до 15 на сложных случаях.

Приём «отсортируй перед жадным алгоритмом» встречается во всём семействе жадных алгоритмов. Interval scheduling (классическая задача про размещение непересекающихся встреч в одной переговорной) сортирует по времени окончания, чтобы первой зафиксировалась задача, которая заканчивается раньше всех. Если у жадного алгоритма есть известное слабое место на неудачно упорядоченных входных данных, предобработка с помощью сортировки часто оказывается самым дешёвым исправлением.

Стоит упомянуть ещё один вариант bin packing. **Best-Fit Decreasing** построен по той же схеме «сортировка, затем цикл», но каждый товар кладётся не в *первый* подходящий bin, а в тот, где после размещения останется *меньше всего* свободного места. В среднем Best-Fit обычно чуть лучше First-Fit, а в стандартной одномерной задаче bin packing у него схожая с FFD гарантия аппроксимации в худшем случае (с той же оговоркой, что этот вариант с двумя ограничениями и суммарным ключом сортировки напрямую классическим доказательством не покрывается). Для этой задачи FFD проходит все тесты, так что тянуться к Best-Fit незачем. На интервью сигнал, который стоит подать, — назвать Best-Fit и branch-and-bound как запасной путь, если нужна точная оптимальность.
