devplus

Платформа для команды: от «что такое интернет» до system design, highload и AI engineering. Теория и практика (код, схемы, промпты) в одном месте.

Обновлено 13 ноября 2026 Этап: оценщик промптов, симулятор system design, Code Review, квизы с контентом Hello Interview и переключатель RU/EN реализованы; следующий — редактор и запуск кода / AI-практика (план) Аудитория: команда (~20 человек), позже публично

Архитектура

Модульный монолит с фоновым воркером. Всё работает на одном VPS через docker-compose.

Браузер→Caddy→/api/* FastAPI·остальное → Next.js→PostgreSQL

Сервисы

web
Next.js (App Router), TypeScript, Tailwind, shadcn/ui
api
FastAPI, Pydantic v2, SQLAlchemy 2 async, Alembic, DI через dishka
postgres
Основное хранилище
redis
Очередь прогонов оценщика
worker
Фоновые прогоны оценщика (Taskiq)
backup
Ежедневный pg_dump в S3-хранилище
caddy
TLS и маршрутизация

Правила

  • Один origin. Без CORS, cookie сессии httpOnly.
  • Типы из OpenAPI. TS-клиент генерируется, CI проверяет, что он актуален.
  • Границы модулей. Модули общаются только через service, зависимости передаёт dishka, правило проверяет import-linter.
  • Режим разработки. ponytail: минимальное полное изменение, известные ограничения помечаются комментарием shortcut:.

Принятые решения

  • Next.js + FastAPI, Python ради AI-экосистемы
  • Модульный монолит вместо микросервисов
  • Вход через GitHub со списком разрешённых пользователей
  • Хостинг: один VPS, docker-compose
  • Уроки: MDX-файлы в git, правки через pull request
  • Интерфейс только на русском. Статьи и квизы Hello Interview доступны и на английском через переключатель RU/EN
  • Оценщик: общий движок для Тренажёра и Лаборатории, Ревью как отдельный режим
  • Порядок: ядро, оценщик, затем симулятор system design
  • Симулятор: движок на сервере (модель потоков и очередей), canvas на React Flow, зачёт по сценариям и AI-разбору
  • DI: dishka
  • Бэкапы: ежедневный pg_dump в S3, хранение 14 дней
  • Очередь задач: Taskiq поверх Redis
  • LLM в оценщике: только Claude, один серверный ключ

Открытые вопросы

  • Judge0 или Piston для запуска кода
  • Библиотека для визуализатора алгоритмов; tldraw или Excalidraw для ER-диаграмм

Задачи на будущее

  • Sentry и метрики. К публичному запуску.
  • Rate limit на входе. К публичному запуску.
  • Открытая регистрация. К публичному запуску.
  • Манифест уроков. Если переименования станут частыми.
  • Kubernetes. Когда упрёмся в один VPS.
  • Агентный режим оценщика. Tool use, агентный цикл, оценка траектории. Когда заработает движок оценщика.
  • Экономный прогон через Batches. Batches API даёт −50% к цене, результат приходит позже. Когда в Лаборатории появятся датасеты на сотни кейсов.
  • Оценщики на Python-коде. После песочницы из подпроекта 5 (редактор и запуск кода).
  • Месячный бюджет на пользователя. К публичному запуску.
  • «Report bad feedback». Кнопка у каждого AI-разбора (оценщик, симулятор, ревью), жалобы в таблицу с привязкой к прогону. Датасет для проверки судьи.
  • Ожидания по уровням. Mid / Senior / Staff в шаблоне кейса модуля 10.
  • Паттерны отдельной группой. Scaling Reads, Contention и другие, со ссылками из разборов. При написании модулей 6, 7 и 10.
  • Проверка поля в симуляторе. Фидбек на каждое из трёх текстовых полей до «Отправить». Решить после первых прогонов симулятора.
  • Квиз на урок и набор для повторения. Вопросы по ошибкам, повторение. После контента первых модулей.
