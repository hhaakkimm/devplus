# Ресерч: Hello Interview (`hellointerview.com`)

**Дата:** 2 ноября 2026
**Зачем:** референс для практики к интервью: шаблон кейса, механика Guided Practice, задачи AI-enabled coding и Code Review. Сравнение с планом devplus и список того, что стоит взять.
**Как собрано:**
- Публичные страницы и JS-бандлы главной: REA 6.7.0 CLI (`analyze-javascript-application`), точечный grep по чанкам.
- Залогиненная сессия владельца Premium в управляемом Chrome (chrome-devtools): списки практик, структура экрана и сетевые вызовы.
- Платные тексты уроков, разборы и эталонные ответы не открывали. Сессии практики не запускали. Одну уже начатую сессию открыли на просмотр: экран и вызовы, без ответов и оценок.
- Контент Hello Interview не копируем. Берём механику, структуру и идеи.

## Курс System Design: как устроен

- Семь групп: In a Hurry, Core Concepts, Question Breakdowns (около 32), Patterns, Key Technologies, Advanced Topics, In the Wild. **[видел]**
- Скелет ответа (delivery framework) с таймингом: Requirements ≈5 мин → Entities ≈2 → API ≈5 → Data Flow ≈5 (необязательно) → High-Level Design 10–15 → Deep Dives ≈10. **[видел]**
- Шаблон разбора задачи: требования → сущности → API → high-level → deep dives (варианты решений с пометкой «плохо / хорошо / отлично») → итоговая схема → ожидания на уровнях Mid / Senior / Staff+ → вопросы для самопроверки. **[видел]**
- Паттерны (Scaling Reads, Contention и другие) вынесены в отдельную группу, из разборов на них ссылаются. **[видел]**

## Guided Practice: механика

- Экран делится на панель вопроса и холст Excalidraw. На панели: название шага, вопрос, вкладки «How To Answer» и «Feedback», кнопки Restart / Exit / Try Again / Next Question. **[видел]**
- Шаг задаётся параметром URL (`?q=non-functional-requirements`), попытка — id в пути. **[видел]**
- Фидбек по шагу структурный: вердикт, «что было хорошо», эталонный ответ по кнопке, «Report bad feedback». **[видел]**
- API: `practice/systemDesign.getBoard`, `saveBoard` (автосохранение холста), `ensureProgressSummary`, `getProgressOverview`. **[видел]**
- «Прочитано» (разбор) и «пройдено» (практика) — два независимых состояния на задаче, плюс History попыток. **[видел]**
- Как AI читает схему и по какой рубрике оценивает: на сервере. **[не видел]**
- Судя по флагам, модели меняются за feature-флагами и разные на разных этапах (практика, оценка, deep dive). **[вывод]**

## AI Coding: два формата

Раздел ближе всего к нашему подпроекту «Редактор и запуск кода». **[видел]**

**Structured: 13 задач (3 Easy, 6 Medium, 4 Hard).** Задачи в браузере: прочитать кодовую базу, починить баг, добавить фичу, оптимизировать под большие входы, всё против тест-сьютов. Формат повторяет раунды CoderPad / HackerRank: три фазы подряд, ассистент выдаётся платформой. Часть раундов — ревью pull request вместе с AI с решением «принять или нет».

**Open-Ended: 8 задач.** Работа локально, в своём редакторе и со своими AI-инструментами. Затем сдача и debrief-вопросы, после них развёрнутый фидбек. Формат повторяет интервью, где собеседник видит экран: стартовая точка — пустой репозиторий или README, строится рабочее приложение с нуля.

Задачи Open-Ended (названия и суть):

| Задача | Суть | Время |
|---|---|---|
| Gridbot | симулятор команд робота на сетке | 45 мин |
| Collaborative Editor | совместный редактор документов | 60 |
| Transcribe | очередь задач транскрибации | 60 |
| LinkLock | сервис входа по magic-link | 60 |
| Fileshare | обмен файлами | 60 |
| Text Render Service | сервис рендера текста в картинку | 60 |
| Schedulr | сервис записи на слоты | 60 |
| LRU Cache | кэш с O(1) | 30 |

Что оценивается (четыре навыка): **[видел]**
1. Решение задачи: разбиение и порядок действий.
2. Контроль над AI: человек принимает решения, AI их исполняет.
3. Привычка проверять: прочитать, запустить, протестировать сгенерированный код.
4. Коммуникация: объяснять, что делаешь.

Итог практики — вердикт hire / no hire с разбором по навыкам. Рубрика, тесты и вопросы debrief не открыты. **[не видел]**

Курс AI Coding: Overview, Fundamentals (ориентация в кодовой базе, планирование, управление AI, проверка и тесты, коммуникация), Common Patterns (графы, топосортировка, backtracking, жадные, DP, парсинг, дизайн структур данных), Problem Breakdowns (около 13). **[видел]**

## Code Review: 8 задач

Читаешь многофайловую кодовую базу, оставляешь комментарии как в PR, получаешь оценку как на интервью. **[видел]**

| Сложность | Примеры тем | Размер |
|---|---|---|
| Easy (3) | сервис оформления заказа, воркер очереди с распределённой блокировкой, лидерборд трат | 3 файла, ~15 мин |
| Medium (3) | multi-tenant API документов, клиентский SDK feature flags, обработчик платёжных webhook | 2–7 файлов, 15–25 мин |
| Hard (2) | цикл LLM-агента (tools, контекст, shell), сервис агрегации ленты | 8 файлов, 25–30 мин |

Первая задача бесплатна, остальные по Premium. Как именно начисляются баллы за найденные проблемы: **[не видел]**.

## Что взять в план

1. **Структурированная AI-практика в песочнице.** Три фазы подряд на одной кодовой базе: починить баг → добавить фичу → оптимизировать. Каждая фаза проверяется своим набором скрытых тестов. Ложится на формат Repair / Build из ресерча LeetCode Projects.
2. **Открытая практика с локальным AI.** Студент делает проект у себя с любым ассистентом, сдаёт репозиторий и отвечает на debrief-вопросы. Worker прогоняет скрытые тесты и AI-ревью. Debrief заменяет наблюдение за процессом: по ответам видно, понимает ли студент код, который сгенерировал AI.
3. **Рубрика «работа с AI» из четырёх пунктов:** решение задачи, контроль над AI, проверка результата, коммуникация. Её можно использовать и для оценки debrief.
4. **Режим Code Review.** Студент читает 2–8 файлов с заложенными проблемами и пишет комментарии. Оценка: сколько реальных проблем найдено, нет ли ложных, качество формулировок. Не требует песочницы, поэтому делается на движке оценщика (судья и рубрика) раньше редактора кода. Хорошая тема: код агентов, очередей, кэшей, webhook-ов, то есть темы наших модулей 4, 5 и 11.
5. **Кнопка «Report bad feedback»** у любого AI-разбора (оценщик, симулятор, ревью): таблица жалоб с привязкой к прогону. Дёшево, и даёт датасет для проверки судьи.
6. **Ожидания по уровням** (Mid / Senior / Staff) в шаблон кейса модуля 10.
