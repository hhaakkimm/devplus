## 1. Цель и рамки

### Что сказал заказчик

- Перенести весь контент из выгрузки Hello Interview на сайт и **перевести всё на русский**.
- Сделать модуль квизов. Квиз проходится двумя способами: после урока и **отдельно, в любой момент** (каталог всех квизов).
- Сохранять прогресс: кто какой квиз прошёл и с каким результатом.
- Квиз показывает верный ответ и объяснение сразу после ответа; в конце экран с результатом, ошибки можно повторить.
- Без рейтингов, таймера и фильтров «на будущее». Уровень вопроса виден значком.
- Остальное исполнитель решает сам.

### Решения исполнителя

- **Два независимых куска, порядок такой:** (1) модуль квизов с 50 квизами, (2) импорт 184 статей.
- **Формат квиза: JSON**, а не YAML. В web нет YAML-парсера, JSON читается стандартной библиотекой, как `_module.json`. Квиз лежит в `content/<NN-модуль>/quizzes/<slug>.json`. Ответы лежат открыто и проверяются в браузере: квиз для самопроверки, скрывать нечего. Поэтому в web-образе они допустимы и `check-images` их не трогает.
- **Slug квиза** `<модуль>/<slug>`, как у уроков. Из имени файла выгрузки `--` превращается в `-` (`core-concepts--caching` → `core-concepts-caching`), повторов быть не должно.
- **Связь с уроком:** во frontmatter урока `quiz: <slug>` (квиз из `quizzes/` того же модуля). Под статьёй появляется блок со ссылкой на квиз и лучшим результатом.
- **Прогресс:** таблица `quiz_results(user_id, quiz_slug, best_score, total, attempts, updated_at)`. Результат присылает браузер, сервер проверяет только границы (`0 ≤ score ≤ total`, `total` 1–200) и формат slug. `shortcut: результат доверяем клиенту, добавить серверную проверку, если появится рейтинг.` Лучший результат определяется по доле `score/total`, при равенстве остаётся прежний. `total` последней попытки перезаписывается: квиз могли пополнить.
- **Устаревшие результаты.** Slug удалённого квиза остаётся в таблице и просто не показывается (как отметки удалённых уроков).
- **Статьи.** Импортированные статьи **не обязаны** следовать шаблону из 6 разделов (раздел 4 обзорной спецификации): это переведённые разборы с собственной структурой. Требуются `title` и `summary` во frontmatter и корректный MDX. Обычные уроки платформы шаблон сохраняют.
- **Модули для статей** создаются по рубрикам источника (раздел 4). Нумерация с 20, чтобы не пересекаться с `00-start`, `10-system-design`, `11-ai-engineering`.
- **Картинки.** Используются только те, на которые ссылаются статьи. Копируются в `apps/web/public/content/<slug>/`. Текст внутри svg-схем остаётся английским (`shortcut: схемы не переводим, добавить, если команда попросит`).
- **Перевод.** Делается скриптом через `claude -p` (вход под Claude Code, как `EVALS_LLM_BACKEND=claude_cli`), скрипт одноразовый и в репозиторий не входит. Правила перевода: обращение «ты», термины и имена технологий остаются английскими, код, команды, URL и имена файлов не переводятся, структура markdown сохраняется. Качество гарантируют проверки формата (раздел 4), а не чтение каждой статьи глазами. Это риск, и он назван в итоговом отчёте.
- **Лицензия.** Материалы принадлежат Hello Interview. Платформа закрытая, для команды; публичный показ потребовал бы отдельного решения. В каждой статье и в каталоге квизов ставится ссылка на оригинал и пометка «перевод».

### Критерии успеха

- Квиз проходится от первого вопроса до результата для всех четырёх типов вопросов. Ошибки можно повторить.
- Результат сохраняется на сервере и виден в каталоге и в блоке под уроком.
- Каталог `/quizzes` открывается без чтения урока, любой квиз доступен напрямую по ссылке.
- Все 50 квизов проходят структурную проверку (загрузчик падает с именем файла на любом нарушении формата).
- Все импортированные статьи компилируются как MDX (`content-compile`), `make lint` и `make test` зелёные.

### Не входит

Рейтинги, таймер, фильтр по уровню, режим «только ошибки всех квизов», перевод текста внутри svg, генерация новых вопросов, проверка квиза на сервере, импорт html-страниц из `research/hellointerview/html/`.

## 2. Формат квиза

```json
{
  "title": "Кэширование",
  "source": "https://www.hellointerview.com/learn/system-design/core-concepts/caching",
  "questions": [
    { "type": "true_false", "level": "junior", "question": "…", "answer": true, "explanation": "…" },
    { "type": "choice",     "level": "mid",    "question": "…", "options": ["a","b","c","d"], "answer": 2, "explanation": "…" },
    { "type": "ranking",    "level": "mid",    "question": "…", "items": ["x","y","z"], "answer": [1,2,0], "explanation": "…" },
    { "type": "matching",   "level": "senior", "question": "…", "left": ["l0","l1"], "right": ["r0","r1"], "answer": [1,0], "explanation": "…" }
  ]
}
```

- `level`: `junior | mid | senior | staff`.
- `choice`: ровно 4 варианта, `answer` индекс верного.
- `ranking`: `answer` перечисляет индексы `items` сверху вниз в верном порядке (перестановка).
- `matching`: `left` и `right` одной длины, `answer[i]` индекс элемента `right`, соответствующего `left[i]` (перестановка).
- Исходные данные: `correctOrder` и `correctPairs` в выгрузке имеют ту же семантику, `MULTIPLE_CHOICE`→`choice`, `TRUE_FALSE`→`true_false`, `RANKING`→`ranking`, `MATCHING_PAIRS`→`matching`.
- `source` необязательна: ссылка на оригинал.

## 3. Модуль квизов

### API (`apps/api/app/modules/quiz/`, модуль `quiz`)

Файлы по правилам проекта: `router.py`, `service.py`, `models.py`, `schemas.py`, `providers.py`. Импортирует только `auth.service`; контракты import-linter по образцу `progress`.

- `GET /api/quizzes/results` → `{results: [{quiz_slug, best_score, total, attempts, updated_at}]}` текущего пользователя.
- `PUT /api/quizzes/{module}/{quiz}/result` с телом `{score, total}` → 204. Путь проверяется шаблоном `^[a-z0-9-]+$`, как у `progress`. Запись идёт одним `INSERT … ON CONFLICT DO UPDATE`, поэтому две параллельные отправки не теряют счётчик попыток.
- Миграция Alembic `quiz_results`, составной ключ `(user_id, quiz_slug)`, `ON DELETE CASCADE` от `users`.

### Web (`apps/web`)

- `lib/quizzes.ts`: загрузчик каталога и квиза из `content/*/quizzes/*.json` с жёсткой проверкой формата (падает с именем файла). Slug из URL сопоставляется со списком имён, в путь не подставляется.
- `lib/quiz-state.ts`: чистая логика (проверка ответа каждого типа, подсчёт результата, список ошибок), покрыта vitest.
- Страница `/quizzes`: каталог, сгруппированный по модулям; у каждого квиза число вопросов и лучший результат «N из M».
- Страница `/quizzes/[module]/[quiz]`: клиентский компонент `Quiz`. Вопросы по одному, после ответа сразу верный ответ и объяснение, затем «Дальше». Экран результата «N из M», список ошибок, кнопки «Повторить ошибки» и «Пройти заново». Результат отправляется при завершении.
- Типы вопросов: `true_false` и `choice` кнопками; `ranking` кнопками «выше/ниже» (без drag-and-drop: работает с клавиатуры и на телефоне); `matching` выбором соответствия из `<select>` для каждой левой строки.
- Блок под уроком: если во frontmatter есть `quiz`, ссылка «Пройти квиз по теме: N вопросов, лучший результат …».
- Пункт «Квизы» в шапке.

## 4. Контент из Hello Interview

Рубрики источника → модули (`content/<NN-модуль>/`), все с `_module.json` на русском:

| Префикс файла в `md/` | Модуль |
|---|---|
| `in-a-hurry--*` | `20-sd-prep` Подготовка к system design |
| `core-concepts--*` | `21-core-concepts` Базовые концепции |
| `deep-dives--*` | `22-key-technologies` Технологии и deep dives |
| `patterns--*` | `23-patterns` Паттерны |
| разборы без префикса | `24-breakdowns` Разборы задач |
| `in-the-wild--*` | `25-in-the-wild` Как это устроено в компаниях |
| `lld--*` | `26-lld` Low-level design |
| `ml--*` | `27-ml-design` ML system design |
| `aicoding--*` | `28-ai-coding` AI coding интервью |

Нумерация уроков внутри модуля `NN-` по алфавиту имён. Квиз кладётся в `quizzes/` того же модуля, что и парная статья; если пары нет, в модуль по префиксу квиза. Сопоставление квиз↔статья делает скрипт по имени с явной таблицей исключений (`key-technologies` ↔ `deep-dives`, `advanced-topics` ↔ `deep-dives`, `breakdowns` ↔ разборы без префикса).

Конвертация md → mdx (одноразовый скрипт): убрать служебные блоки («Try it yourself first», навигацию, баннеры), `{`, `<` вне кода экранировать, ссылки на hellointerview заменить на ссылки на уроки платформы там, где парная статья есть, иначе оставить внешней, картинки перенаправить на `public/content/`.

### Проверки импорта

- `content-compile` компилирует все новые mdx.
- Тест на соответствие: у каждого `quiz:` во frontmatter есть файл квиза; у каждого квиза корректный формат.
- Скрипт перевода сверяет число блоков кода и картинок до и после; расхождение перезапускает статью.
